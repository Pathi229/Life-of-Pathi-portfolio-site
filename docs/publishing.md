# Publishing from the dashboard

Create the first administrator with `php artisan pathi:admin`; sign in at `/admin`. Counts appear on the overview; each resource’s Create action is available from navigation. There is no public sign-up.

1. **Branch:** open Branches, Create, enter a name and readable slug, description, activity, parent if any, and order. Parent cycles are rejected. Archive a branch to remove it from the overview while preserving its historical page and linked work.
2. **Channel:** open Channels, create a collection, set its introduction/accent, associate branches, and optionally choose a cover uploaded through Media. Social links accept labelled HTTPS destinations. Publishing collections are distinct from branches.
3. **Media:** upload a JPG, PNG, WebP, PDF or text download (up to 10 MB); set alt text, caption and credit. Files remain private until associated with accessible content or explicitly selected as a channel cover/CV. Reuse the same media record in several entries. Uploaded images are resized to fit 1600×1600 in the browser without upscaling; reorder the project/article media selections to organise a gallery. Remove all references before deleting media.
4. **Project:** open Projects, create a title, unique slug, summary and Markdown story. Set the primary branch, related branches/channels, role, dates, maturity and reusable media. Save a draft first. Use Preview for an admin-only signed link lasting 20 minutes. Set Published and Public to appear in discovery immediately. Mark Feature for prominent collection placement; order is explicit.
5. **Article:** open Blogs & Guides, use the Markdown editor, add collection/difficulty/technique metadata, optional project and series. The sequence number is used in both series and project navigation. Leave gaps (10, 20, 30) for easy insertion. Standalone posts need neither project nor series. Create a Series record first when needed.
6. **Video:** choose a supported HTTPS YouTube/Vimeo URL, write useful context and optionally link a project/article. The site provides a deliberate external playback link, avoiding autoplay and third-party tracking until clicked.
7. **Work:** projects appear in Work only when Include in Work is enabled, published and public. Populate the case-study fields with context, contribution, process, deliverables, outcome, lessons, credits and evidence. Do not invent metrics; clearly identify concept/demo work. Order projects using sort order.
8. **Settings:** edit identity, homepage introduction, featured reading pathway, optional CV, contact/availability, social links, and dated Now content.

Publication (Draft/Published/Archived), visibility (Public/Unlisted/Private), maturity (Seed/Growing/Fruit) and branch activity (New/Active/Dormant) are independent. Unlisted entries can be opened by URL but are excluded from search, collections and sitemap; they are not confidential. Private/draft content requires an admin session, including previews. Published dates in the future suppress public access until that date. Meaningful update dates track text changes separately from publication.

Changing an entry, branch, channel or series slug retains a redirect. Old entry URLs stop working when the target is archived/private. Delete actions are recoverable; select the deleted-record filter to restore content. Relationships use restrictive foreign keys to protect unrelated records. Replace or archive demonstration records before using the website as a real portfolio.
