# Architecture and decisions

Laravel 12 + Filament 4 + PHP 8.4 are compatible stable versions. Compatibility was verified against the official `laravel/framework` 12.x and Filament 4.x Composer manifests on GitHub; Filament support declares Laravel 11.28/12/13 and requires intl. Exact dependencies are recorded in Composer/npm lockfiles. The normal documentation hosts were inaccessible under the cloud network policy.

Projects, articles and videos use one typed `entries` table and three Filament resources. This centralises visibility, slugs, SEO, maturity, dates, media and reusable collection relationships. It avoids duplicating projects reached from channels or branches. Database foreign keys prevent destructive relationship cascades. A project relationship must point to another project; a video’s article relationship must point to an article. Series/project journeys share each entry’s sequence, with ID as a deterministic tie-breaker.

Branches are nested and cycle-checked. Parent branch pages and filters include their active nested pathways. Channels are audience collections connected to several branches. Many-to-many pivots connect entries to branches/channels and reusable media. Site settings are a singleton. Case-study text is structured key/value data and only explicitly curated projects appear in Work. Admin users require `is_admin`; no registration endpoint or seeded credentials exists.

Every public listing uses `discoverable()`; direct entry URLs allow published public/unlisted records whose publication date has arrived. Draft/private access is admin-only. Signed previews additionally require an authenticated admin and expire after 20 minutes. Media are stored privately; a checked serving route validates their content context, MIME type and access on every request. Files are never copied to a public storage link. Explicit CV/cover selection makes that file public. Rich text uses Markdown with raw HTML stripped and unsafe links disabled. Video links permit only HTTPS on supported domains, with external playback rather than arbitrary embed scripts.

The botanical SVG is deliberately deterministic. Dashboard branch order drives label and control order. It shows the first eight top-level labels and presents all branches as large controls, with normal branch links and list browsing. Selecting a control highlights its corresponding SVG label and reveals a nearby panel. Nested branches live in their parent pages. Keyboard, touch and reduced-motion support do not depend on dragging or hover. A small JS module adds interactions and article contents; public navigation works without it. English and Sinhala use Unicode, system font fallbacks and a locally hosted Noto Sans Sinhala WOFF2 font (SIL Open Font License). The font was sourced from the official Google Fonts repository and converted to WOFF2; its licence is included. A small local subset of Noto Sans Symbols 2 supplies botanical marks and arrows consistently. Admin avatars and fonts require no third-party account or remote avatar service.

No content cache is used, so publishing immediately changes pages, search and sitemap. Lists paginate. Images load lazily and use bounded responsive layouts. The dashboard image upload pipeline bounds images to 1600×1600 without upscaling, and galleries use an ordered media pivot. Additional server-side thumbnail generation is a future optimisation. Uploads are limited to safe formats and 10 MB. There is no enquiry form, email delivery, external account connection, scraping or automated social import. Featured selection is a per-entry flag shared across associated collections, rather than different per-collection feature rankings. Homepage selected work, growth and recency use database queries; Settings chooses the featured reading pathway.

Future extensions: per-collection feature ordering, automatic responsive image derivatives, more sophisticated SVG layout, multi-user trees, company forests and authorised platform integrations. These do not change the shared content identity or access rules.
